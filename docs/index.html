03

How it works

  1. STEP 1wrap

    Dry-runs each method on a near-sandbox copy of the target, then signs one AddKey: a function-call key scoped to the receiver, the allowed methods and a gas allowance.

    KEY LOADEDoperator full-access key, 1 tx
  2. STEP 2serve

    Serves the allowed methods to an MCP client as tools, and signs each call with the session's function-call key.

    KEY LOADEDone function-call key
  3. STEP 3inspect

    Reads the key's scope with view_access_key and the target's code hash, and prints the cage card.

    KEY LOADEDnone
  4. STEP 4burn

    Deletes the key, or the whole session sub-account. Later calls are refused: AccessKeyNotFound or SignerDoesNotExist.

    KEY LOADEDoperator full-access key, 1 tx

The RPC node validates every transaction before anything reaches a block. Keyhole never holds a full-access key while it serves the agent.

05

Run it yourself

Node 22.22.2 or newer. Clone github.com/mdlog/keyhole, then from the repo root:
  1. 1 · OFFLINE
    npm ci && npm test

    Replays the recorded evidence with no NEAR node and no network request. See seven REPLAY [ lines ending PASS: refused by protocol (NAME), then secret scan: 0 keys in repo.

  2. 2 · NETWORK
    npm run keyhole -- demo --sandbox

    Boots a private near-sandbox node (about 90 MB on first run), wraps a key, votes, makes four out-of-scope attempts and burns the key. See RESULT 20/20 PASS and exit 0.

  3. 3 · TESTNET
    npm run keyhole -- demo --testnet

    Needs KEYHOLE_OPERATOR set to a funded testnet account. See 14 steps, each landed transaction linked to the explorer, and RESULT 14/14 PASS.

SIGNING
